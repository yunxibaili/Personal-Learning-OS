Tutor Runtime

Sequence — Context → Prompt → Provider → Response · M4.5

1
User
selects concept + asks question
2
TutorPanel
captures concept_id + query + mode
3
Router
POST /api/v1/tutor/test — parameter validation
4
Context Builder
build_tutor_context() — concept + mastery + mistakes + related + review
5
Prompt Builder
build_prompt() — pure function, no I/O, dual security filter
6
Provider
LLMProvider.complete() — 30s timeout, 3 retries
7
LLM
external API — OpenAI-compatible HTTP
8
Response
structured text + action suggestions
9
User
reads explanation / hint / review prompt
LLM is forbidden from:
  • Writing to SQLite database
  • Modifying concept_mastery
  • Creating or deleting concepts
  • Calling review_scheduler
  • Accessing vault file contents
  • Reading API keys or settings
State changes go through:
  • learning_event (append-only) → mastery calculation → state update
  • User action in Dashboard → POST /review/{id}/answer
ADR-014 frozen boundary: LLM reads context, generates text. All writes go through event system.
