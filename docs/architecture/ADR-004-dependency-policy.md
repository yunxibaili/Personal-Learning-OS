# ADR-004: 依赖管理制度化

日期：2026-08-26 · 状态：Accepted

## Context
项目早期已在多个方案间裁决（拒 ORM/LangChain/D3/Tailwind、延后向量库、
Zustand 三选二等）。这些决定散落在讨论记录中，存在被未来会话"无意加回来"
的风险；同时缺少新增依赖的标准化门槛。

## Decision
1. 采纳"能力复用优先级链"为强制阶梯（标准库→现有代码→现有依赖→成熟开源→新依赖/自研）
2. 新增依赖必须通过 Dependency Review 六连问，并按模板登记进
   `docs/dependencies/REGISTRY.md`，答不全不准加入
3. 已否决备选固化在 TECH_DESIGN §3.2，禁止回潮
4. 每个里程碑结束执行依赖审计（未使用/重复/间接/过时/高风险/可被 stdlib 替代/可删除）
5. 目标是最小的合理依赖集合，而非数字上的最少

## Alternatives Considered
- 无制度、凭感觉：已被证明会导致依赖膨胀与决策漂移
- 完全禁新增依赖：不现实，会逼出自研大轮子，同样提高维护成本

## Reason
把散落的个案裁决上升为可执行流程，保护长期轻量性与可维护性。

## Consequences
- 每次引依赖有固定文书成本（一份登记），换取长期可控
- 审计每里程碑一次，结果记入 CHANGELOG
