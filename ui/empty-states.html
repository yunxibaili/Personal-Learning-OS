Empty States · ADR-013 §2.13

空状态与首次引导

空状态不是「没东西可显示时的兜底」，它是新用户看到的第一个界面。 本项目把它分成两类：加载中走骨架屏（Skeleton）， 真的没有内容且只有一条路可走时才允许聚光引导（Spotlight）。

本页给出 web/src 中全部 12 个空态分支的逐条判定， 以及 8 个动效基元的落点清单。规范依据 ADR-013 §2.13。

2026-09-02 所有者裁定

本页是规范，不是施工单。Spotlight 与动效基元暂不写入 web/ 业务代码， 沿用「组件先在 ui 库定稿」的既有裁定（与 M9-007 回灌同一节奏）。 接线另开任务，开工时以本页的落点清单为准——不要重新盘点一遍。

① web/src 空态全量审计

逐条按三条门禁判定。门禁 1 看界面有没有内容可读，门禁 2 看卡内是不是只有一个 CTA （卡内 button 数 = 1，关闭与辅助链接不计），门禁 3 由实现保证（仅 hover + media query 包裹）。 三条缺一不可。

允许 三条门禁全过 补条件后允许 门禁 2 差一个 CTA，补上即可 禁止 门禁 1 不满足（有内容可读）或应走其他模式

④ 动效基元落点清单

8 个基元在 web/ 里已全部实现，但一个都没进业务页面—— 它们全部只躺在 web/src/dev/ComponentGallery.tsx（ToastProvider 只挂在 App.tsx:90，useToast() 业务调用数为 0）。

顺带一个更大的发现：全量 19 个 components/ui/ 导出组件里， 只有 Progress(3 处) · Badge(1 处) 进了业务， Button 的业务引用数是 0。 所以这不是「动效基元找不到落点」，是整个组件层都没接线——接线要整体排期，不是补几个点。

⚠ 接线阻塞项：.btn-primary 与 §2.13 冲突。 空态规范（本页 ⑤）要求主 CTA 为 --brand-deep 纯色底 + --text-inv 白字； 但 web/src/global.css 的 .btn-primary 实为 linear-gradient(135deg,var(--brand),var(--brand-2)) + box-shadow:var(--shadow-glow)。 这同时违反两条：ADR-013 §2.7 禁 gradient / glow，以及 §2.13 line 291「按钮渐变、渐变背景 —— 本例外不豁免这些」。 因此 4 处「补 CTA 后允许」的落点不能直接用 <Button variant="primary">——那会把被禁的渐变带进空态卡。 接线前须先定：新增纯色 CTA 变体 / 就地修 .btn-primary / 空态专用类覆盖。 （本页 ② 演示用的是 .sl__cta 纯色实现，不受此问题影响）
