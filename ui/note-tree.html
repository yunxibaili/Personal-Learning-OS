M-NOTE-TREE · 左栏多层级笔记列表

层级是视图，不是目录

主/副笔记是严格单父关系（子笔记 frontmatter 写 parent: "[[父标题]]"， 事实源在 Markdown）。左栏把它渲染成一棵一层树：主笔记 = 可展开行， 副笔记 = 缩进子行。底层允许 parent 链，但 V1 界面只渲染一层——星球 / 卫星。 本页组件可交互：点击、展开、过滤、键盘导航全部真实生效。

这条左栏在演示什么。「优化器」「注意力机制」是主笔记（星球），缩进的 Adam、SGD 是挂在它们下面的副笔记（卫星）。层级只用了一个通道：缩进 + 父/子两级字重；品牌橙只出现在选中行；右侧徽章是副笔记计数；「未挂载」组单独用警告色——因为 parent: "[[ResNet]]" 指向的笔记不存在，按裁决保留原值并标记，绝不自动删除。

交互。 整行点击打开笔记；› 箭头是独立命中区，只管展开/收起。 键盘：聚焦树后 ↑↓ 移动， → 展开，← 收起（子行按 ← 回到父行）。 过滤时命中行保留、其祖先链自动展开，计数徽章与分组标签隐藏，避免「搜到 3 行却看到 3 个组头」的噪声。

与数据层的接线。树由关系解析层（resolve_hierarchy()）产出： 显式 parent 优先，wikilink 拓扑推断只作 legacy fallback； 一个笔记最多一个父级；无父级笔记按现有平铺顺序排在树后。 展开/收起状态属于视图状态，可存本地但不进 vault、不进 SQLite。

规范

组件只做渲染与交互；层级来自关系解析层，本组件不做任何推断。

数据规则（来自 ADR-024 裁决链）

规则约定
事实源子笔记 frontmatter parent: "[[父标题]]"；Markdown 是唯一权威，DB links(relation=parent) 只是可重建的派生索引
单父一个笔记最多一个 parent；vault 可形成多棵树（forest）。底层允许 parent 链，V1 界面只渲染一层（星球/卫星）
权威优先显式 parent > 拓扑推断；树数据统一来自 resolve_hierarchy()，本组件不自行推断
orphan（无效父级）parent 指向不存在的笔记 → 子笔记进「未挂载」组，保留原值 + 警告标记，绝不自动删除 parent（用户写错一次不能毁掉原始意图）
展开状态纯视图状态：可存 localStorage，不进 vault、不进 SQLite

交互规则

操作行为
点击行打开笔记并置为 active（brand-soft 底 + 2px 橙左缘）；若该行处于收起的父级内，先展开祖先链（跟随打开笔记）
点击 › 箭头仅展开/收起，不切换 active——两个命中区分离，消除「想展开却打开了笔记」的误触
无子级的父行箭头占位但不可见可点（对齐网格），不显示计数徽章
过滤框输入标题含关键词的行保留；命中行祖先自动展开并显示；无命中后代的分支隐藏；计数徽章与分组标签暂时隐藏；零命中显示「没有匹配的笔记」
清空过滤恢复完整树；展开状态回到过滤前的用户选择
↑ ↓在可见行间移动 active（循环）
→ / ←展开 / 收起当前父行；子行按 ← 回到父行

业界对照（为什么这么做）

来源做法本项目取舍
Notion 侧栏整行点击打开页面；箭头独立区域只管展开；页面树一行一节点采纳「行/箭头双命中区」——这是展开类列表误触最低的范式
Obsidian · Nested Pages 插件Notion 式树 + 过滤时命中分支自动展开 + 跟随 active 展开祖先 + 展开状态持久化采纳三条交互；持久化只存 localStorage（视图状态不进事实源）
Obsidian 原生文件树文件夹即层级，扁平双链世界观印证本项目「层级是视图不是目录」——不建真目录，vault 保持扁平
VS Code 资源管理器→← 展开/收起、↑↓ 移动的树键盘语义采纳键位（与 M9 视觉引擎的方向键互不冲突：上下文不同）
