ui 库 · 组件 · dot-earth.html

Dot Earth · 点阵地球 + 多轨卫星

主页 Hero 的主视觉：一颗点阵地球自转，多条近地轨道环绕， 每颗卫星是一个颜色的球体，沿轨道拖出墨色渐隐尾迹。 地球本体只有点阵大陆轮廓，没有中间那些彩色节点连线 —— 概念网络归 GraphView，这里只保留「星球 + 轨道卫星」两层。

落位：主页 Hero 与全屏「星系」浮层 —— 只在这里，不进笔记。 它照 mimo.mi.com 的地球来，尺寸天然大（建议 ≥ 320px，Hero 用 460px）。 笔记区一颗星球都不放：2026-09-02 取消「卫星 = 笔记」映射后， 88px 的 Mini Star 也从笔记卡右上角撤掉，退为纯规范页。理由见 §②、§⑤。

①组件本体

三个尺寸，同一份实现。点阵大陆来自 assets/dots-world.png（正像 + 水平镜像预拼成无缝长条，横向滚动 = 自转）。 卫星颜色取自项目既有的域调色板（与 home-hero.html / KnowledgePlanet.tsx 同源，未新造颜色）。

200 × 200
3 卫星 / 2 轨。地球直径 100px，点距 1.43px —— 点阵糊成一片，只适合极窄场景。
260 × 260
4 卫星 / 3 轨。地球直径 130px，点距 1.86px —— 点阵勉强可辨，下限。
320 × 320
4 卫星 / 3 轨。地球直径 160px，点距 2.29px —— 点阵清晰，组件内推荐尺寸；Hero 用 460px。
为什么地球不能再小。贴图实测 2000×1049，原始点距 15px、点宽 6–7px；球面可见宽度约等于地球直径， 映射后点距 = 直径 ÷ 1049 × 15（直径 = 容器 × EARTH_D，现行 0.50）。 实测四档：200px 容器 → 直径 100 → 1.43px（糊）；260 → 130 → 1.86px（勉强，下限）； 320 → 160 → 2.29px（清晰）；Hero 的 460 → 230 → 3.29px（清晰）。 这也是为什么「右上角星球」不能继续用 88px 的小星：88px 装不下点阵（直径仅 44px → 点距 0.63px）， 只能是无贴图的纯色星球（即 mini-star.html）。

②落位：进 Hero，不进笔记

2026-09-02 所有者裁定：「点阵地球不要放在笔记里，太大了。」「优化器就不用显示卫星系统了。 也不用搞笔记增加卫星增加了，这个点阵地球就是主页的固定动画。」
它的位置照 mimo.mi.com 来 —— 主页 Hero 的主视觉，且只在这里。 同一轮裁定同时取消了「卫星 = 笔记」的映射：笔记区现在一颗星球都没有，标题旁不再放 88px 的小星， mini-star.html 因此退为纯规范页（当前无页面消费）。
于是只剩两档，各自只做自己装得下的事：Hero ≥ 320px → 点阵地球；笔记区 → 全静态，无星球。 中间那档（100–280px）两边都不占：点阵糊、纯色星球又失去语义 —— 不做。

③规格表

挂载方式：<canvas data-dot-earth>，脚本自动扫 canvas[data-dot-earth] 并逐个挂载，逐 canvas 幂等。

项取值说明
挂载选择器canvas[data-dot-earth]同页多实例互不干扰；window.__dotEarthBootAll(root) 供动态渲染复用
尺寸由 CSS 容器决定ResizeObserver 跟随容器；建议 ≥ 320px（点距 ≥ 2.2px 的可辨下限）；260–300px 为「勉强」，< 200px 点阵糊成一团
地球直径容器 × 0.50半径 = 容器 × 0.25（常量 EARTH_D）。与 home-hero.html 的 0.733 不同——本组件要给轨道留边；早期按 0.60 做过，实测球把轨道压住了，收到「球体有点大」后下调
点阵贴图assets/dots-world.png2000×1049；正像 + 水平镜像预拼成 4000px 无缝长条，横向滚动 = 自转，接缝天然对齐
自转速度0.030 × 地球直径 / 秒data-spin 可选 slow 0.012 / normal 0.030 / fast 0.055；与页面尺寸无关，缩小不减速
轨道数1–4（默认 3）data-orbits；rx/ry 为地球半径倍数，tilt 错开：1.24/-0.20 · 1.40/0.44 · 1.56/-0.64 · 1.70/0.86
轨道不裁切自动 fit 缩放最外轨半径 + 卫星半径 > 画布半宽时整体等比收缩，轨道永不出血
卫星数0–16（默认 4）上限同性能契约；超过 6 颗时颜色回退中性灰（见 §④）
卫星颜色域调色板 6 色#7c93ad · #c9a86a · #8aab8e · #a08cb4 · #b48a8a · #6fa3b8 —— 与 home-hero.html 同源，未新造
卫星大小地球半径 × 0.085 – 0.160由 w（0–1，可映射字数或链数）插值，不传取 0.5。460px 容器 → 9.8 – 18.4px 半径。
两轮实测定档，别再改：曾照抄 home-hero 比例（0.024–0.059）→ 只剩 3.4–6.8px，被指「太小」；上限再往上，拖尾线宽（headR × 0.8）会先糊成一片
球后卫星可见，不遮挡depth = sin(phase) ∈ [-1,1]；不透明度 0.725 + depth×(depth≥0 ? 0.225 : 0.20) → 0.95（球前最近）/ 0.725（侧边）/ 0.525（球后最远），两侧在 depth=0 收敛、连续无跳变；半径另乘 0.8 + 0.2×depth。
不要改回「球后先画、被地球盖住」的真遮挡：卫星只有几 px，地球边缘扫过它只要 0.04s，真遮挡就是每圈约 3 成时间整个消失，进出像卡了一下
墨色拖尾弧长 1.1 rad / 9 段INK = [32,34,40]，逐段 alpha 0.38 × fade × baseAlpha，线宽 headR × 0.8 × fade，lineCap: round
深度表达sin(phase) 判前后见上「球后卫星」一行：不做遮挡，用不透明度 + 半径表达远近。轨道环仍按前后半段分开画（后半段被地球盖住 —— 环绕到球后是对的）
帧率上限 60fps · 单 rAF不沿用性能契约的 30fps：地球自转只有 ~7px/秒，30fps 下每帧走 0.23px，点阵会读成「一格一格」。代价由预缩放/预渲染抵消。
节流判断留 6ms 容忍窗口（FRAME_TOL）——60Hz 帧间隔在 16.6–16.9ms 抖动，硬比 FRAME_MS 会让「两次 vsync」偶尔差一点不到阈值而整帧跳过，于是 33ms/50ms 交替，这正是「掉帧、不连贯」的根因
贴图预缩放 + 预烘焙4000px 无缝长条按渲染尺寸预缩一次（strip），周期取整 → 接缝落整像素；暗角 + 顶部柔光烘成一张叠加图（overlay）。每帧只剩 1:1 位块传输，不要改回每帧 drawImage(seamless,…) 带缩放
dprmin(devicePixelRatio, 2)与 home-hero.html 一致
离屏暂停IntersectionObserver + visibilitychange不可见即停 rAF，回来再起
reduced-motion静态一帧不自转、不公转；拖尾保留（它是静态几何，不是装饰动效）
点击派发 dot-earth:pickdetail: { hit, index, name, clientX, clientY }；命中半径 = max(卫星半径, 8) × 2.2
指针跟随无刻意不监听 pointermove——不与页面的聚光/悬浮抢指针
禁止彩色节点连线 / gradient / backdrop-filter球面概念节点 + 连线已于 2026-08-29 从 home-hero.html 移除，本组件同样不引入；概念网络归 GraphView

④与 Mini Star 的关系 · 以及「彩色卫星」的边界

两个组件曾是同一隐喻的两个尺度。2026-09-02 取消「卫星 = 笔记」映射后，只有大尺度还在用：Dot Earth 是主页 Hero 的固定动画，Mini Star 退为无页面消费的规范页。下面的对照保留，是为了说明小尺度为什么在笔记区也停了 —— 不是尺寸问题，是语义问题。

Dot Earth（本页）· 主页 Hero 主视觉

  • 尺寸 ≥ 320px（Hero 用 460px），有点阵贴图，地球自转
  • 用在主页 Hero —— 唯一落位；笔记区、列表、角标一律不复用
  • 卫星可多色（≤6，>6 回退中性灰）
  • 成本：一张 306KB 贴图 + 每帧若干次 1:1 位块传输（贴图长条 + 叠加层 + 每星一次光晕）
  • 卫星不再代表笔记：它现在是 Hero 的装饰层，点选派发 dot-earth:pick 但不绑定笔记

Mini Star · 小尺度版（当前无页面消费）

  • 尺寸 56–96px，纯色中央星球，无贴图
  • 曾用在笔记卡右上角；2026-09-02 移除 —— 卫星不再映射笔记后它失去语义
  • 卫星中性灰 + 橙描边（装不下色相）
  • 成本：纯几何绘制，零资源
  • 留着不删：将来列表行 / 侧栏 / 卡片角标若需要小星，从这里取，不要新写
「每颗卫星一个颜色」的适用边界（2026-09-02 所有者裁定，据此放宽既有约束）。 既有约束是「形状即语义、橙只作注意力指针、不用于静态分类」（ADR-013 §2.x / ADR-023）。 彩色卫星等于新增一个色相编码通道，因此必须封边，否则会被稀释成又一套彩虹分类：
  • ≤ 6 颗：可用域调色板区分（Hero 情形：梯度下降与优化器 / Attention 机制笔记 / SM-2 复习算法 / 卷积网络读书笔记 = 4 颗）
  • > 6 颗：色相开始难辨，回退中性灰 + 橙描边，改用位置与轨道区分——同 Mini Star
  • 颜色只作身份标识，不承载掌握度 / 状态 / 时间等第二重语义；那些仍走 ProgressRing 与文字
  • 选中态仍只用橙（brand-soft 底 + 左缘橙条），不改为「把卫星变橙」

⑤结论

点阵地球不进笔记；它属于主页 Hero

三个落位都真实渲染过：塞进笔记主卡的 300px 太大（压标题、抢注意力、挡动线）， 硬缩到 150px 又点阵糊了（地球直径只剩 75px、点距 1.07px，不到可辨下限 2.2px 的一半）。 两条路都堵死 —— 说明它压根不该在笔记里，而不是尺寸没调好。

主页 Hero 是它唯一站得住的位置：mimo.mi.com 的地球就在这里； Hero 是「看」的地方不是「读」的地方，自转不抢注意力； 460px 的画布给到地球直径 230px、点距 3.29px，点阵清晰，4 轨 4 星的多轨形态才成立。

笔记区一颗星球都不放。2026-09-02 所有者裁定「优化器就不用显示卫星系统了」， 「卫星 = 笔记」这套映射取消 —— 小尺度的 88px Mini Star 也一起撤掉，不再只是换小一号， 因为失去语义的图形换成任何尺寸都还是装饰。

已落地的三处： ui-preview.html §hero 把手画的 CSS 圆占位换成真实组件（460px / 4 轨 / 4 星，脚本由 sync-dot-earth.mjs 从本页同步）； note-workspace.html 与 ui-preview §2 的「优化器」移除整个星球系统，标题回到单列 （.star-card → .note-head），现在是零 canvas、零 rAF， 只保留 chip ↔ 卡的双向锚；mini-star.html 留作规范页，当前无页面消费。
