泰勒展开的核心想法只有一句：用多项式去模仿一个函数在某一点附近的行为。 为什么是多项式？因为多项式是唯一一类「求值只靠加减乘」的函数——计算机喜欢，手算也喜欢。

一阶：先模仿位置与斜率

如果只要求在 x₀ 处函数值相等、切线斜率也相等，那唯一的选择就是切线： 

f(x) ≈ f(x₀) + f'(x₀)(x − x₀)

这已经能算 sin(0.1) 了，误差约 0.00017。但离 x₀ 越远， 直线就越跟不上曲线的弯曲。

二阶：把弯曲也算进去

再加一项，让二阶导数也匹配上，直线就变成了抛物线： 

f(x) ≈ f(x₀) + f'(x₀)(x − x₀) + f''(x₀)/2! · (x − x₀)²

2! 不是凑出来的。二阶导是「二阶差商的极限」，而差商天然带着 1/2! 这个系数 —— 见 中值定理三者关系。

直觉：n 阶展开 = 让两个函数在 x₀ 处的前 n 阶导数全部相等。 模仿得越像，能走的距离越远。

余项：误差去哪了

泰勒定理最有用的部分其实不是多项式，而是余项。拉格朗日余项告诉我们： 

Rₙ(x) = f⁽ⁿ⁺¹⁾(ξ) / (n+1)! · (x − x₀)ⁿ⁺¹   ，ξ 介于 x₀ 与 x 之间

它把「近似有多准」转换成「n+1 阶导数量级有多大」。这也是为什么 eˣ 特别好算：它的任意阶导数都还是 eˣ，在 [0,1] 上 一致有界，余项随 n 阶乘级衰减。

一个反例

存在「光滑但泰勒级数不收敛回自身」的函数，例如 f(x) = e^(−1/x²)（并定义 f(0)=0）。它在 0 处的各阶导数全为 0， 泰勒级数是恒等 0，但函数本身不是。光滑 ≠ 解析。

笔记优先：把主次关系纠正过来

原结构把笔记、图谱、Universe、导图、AI Tutor、复习、仪表盘做成七个平级入口。 笔记占七分之一，可视化占七分之三。这个原型把关系反过来： 笔记是工作区，其余都是写作时的上下文。

三条判断依据

  • 默认值即产品定位。 打开应用看到什么，什么就是主线。七个平级 tab 等于宣称「这七个同等重要」——而它们并不。
  • 笔记是产生价值的地方，其余是加工品。 图谱、掌握度、复习队列全部由笔记派生。没有笔记就没有它们，反过来不成立。
  • 写作是脆弱状态。 编辑器上任何多余控件都是在邀请用户中断思路。AI、搜索、可视化一律退到右栏，需要时再伸手。
关于架构原则的一处张力。 docs/adr/principles.md 的「核心创新投入方向」列了五类： Knowledge Graph · Learning Memory · AI Tutor · Visual Learning Engine · Personal Learning OS —— 没有笔记。这条原则隐含的前提是「笔记是成熟能力，用现成编辑器接上就行」。 工程上这没错，但它不该顺带推导出「笔记在界面上也不重要」。 建议在该节补一句：以上五项是建立在笔记之上的差异化能力， 笔记本身是载体与入口，界面权重要相应体现。
